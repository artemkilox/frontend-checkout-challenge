# Оформление заказа

Фронтенд тестового магазина: каталог, корзина, оформление и тестовая оплата. Бэкенд — из исходного задания, не менялся.

Исходные условия: [задание](docs/ASSIGNMENT.md) · [API](docs/INTEGRATION.md) · [критерии](docs/EVALUATION.md). Для отклика нужен ещё [канвас](https://github.com/instatdigital/frontend-canvas-challenge) — это отдельный репозиторий.

## Запуск

Нужны Node.js 24.x и npm 11.x.

```sh
git clone https://github.com/artemkilox/frontend-checkout-challenge.git
cd frontend-checkout-challenge
npm ci
npm run dev
```

- API: http://127.0.0.1:4000 (Swagger: http://localhost:4000/docs/)
- Фронтенд: http://localhost:3000

По отдельности: `npm run dev:api` и `npm run dev:web`.

Сборка:

```sh
npm run build
npm start
npm run start:web
```

Адрес API для фронта по умолчанию `http://127.0.0.1:4000`. Другой — `apps/web/.env` из `apps/web/.env.example`.

Товары учебные. Для формы: `buyer@example.test`, телефон `+7 999 000-00-00`. Карту не вводить: в форме оплаты только тестовые карты из API.

Сброс данных API: остановить сервер, `npm run data:reset`, затем новая сессия в браузере (или очистить localStorage).

Корневой `npm run check` — формат, тесты бэкенда и OpenAPI. `npm run smoke` — при запущенном API.

## Как устроен фронтенд

Workspace `@checkout/web` (Next.js App Router). Подробнее по файлам: [apps/web/README.md](apps/web/README.md).

- Один HTTP-клиент (`apps/web/src/api/client.ts`): база URL, заголовки, JSON, пустой `204`, разбор envelope `data` / `error`. Компоненты не вызывают `fetch` и не смотрят на `Response`.
- Ресурсы (`src/api/resources`) только описывают путь и тело.
- Опрос оплаты (`src/api/poll.ts`) общий: AbortSignal, стоп при финале или уходе со страницы, устаревший ответ отбрасывается.
- Сессия и идемпотентность — `localStorage`; черновик полей оформления — `sessionStorage`, чтобы ошибка запроса или F5 не стирали форму.
- Экраны в `src/features`, маршруты в `app/` без логики API.

Отказ карты — это `payment.status === failed` при HTTP 200, не ошибка сети. Страница заказа читает статус с сервера: успех карты только при `paid` + `succeeded`.

## Обработка данных

Каталог часто читает «сколько этого товара в корзине». При смене корзины один проход по `items` собирает `Map<productId, quantity>`. Карточка делает `Map.get`, без `find` по массиву на каждый товар. Промежуточный массив не создаётся. `Map` живёт, пока корзина та же; ввод имени в форме его не пересобирает.

## Принятые решения

- Next.js App Router, клиентские экраны (сессия, опрос, storage).
- CSS Modules и имена БЭМ, без UI-kit.
- Пути API заданы в клиенте по контракту, не через `links` из ответов.

## Проверенные сценарии

- Каталог, товар без остатка, количество на карточке и в корзине.
- Пустую корзину нельзя оформить.
- Самовывоз и курьер; суммы доставки и итог с `/api/quotes`.
- Наличные: «Заказ оформлен, оплата при получении».
- Карта: успех, отказ, отмена, повтор того же заказа.
- Перезагрузка: сессия и корзина; незавершённая оплата продолжает опрос.
- Список «Мои заказы» в рамках гостевой сессии.

## Недоработки

- Нет деплоя и аккаунта покупателя (по заданию не нужны). Сессия живёт в браузере; другой браузер — другая корзина.
- Вёрстка спокойная, без анимаций.
